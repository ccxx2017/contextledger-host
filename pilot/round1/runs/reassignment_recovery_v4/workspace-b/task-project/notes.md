## 1. 背景与范围
- 只重构 `run_backtest` 的实现：Python 逐日循环 → numpy 向量化，并新增结果缓存。
- 不改策略规则，不改对外 API：`run_backtest(prices) -> {"final_value": float, "trades": int}`。
- 已知语义怪癖按基线保留：`trades` 是「期末剩余持仓数」，不是成交次数

## 2. 实现要点

### 2.1 向量化
- 涨跌判定一次差分完成：`up = p[1:] > p[:-1]`（严格 `>`，持平视为非上涨，与基线一致）。
- 策略可等价刻画为「连续上涨段」：
  - 段内每个上涨日各买入 1 份（现金流 `-p[i]`）；
  - 段被其后首个非上涨日 `j` 终止时，当日全部清仓（现金流 `+p[j] * 持仓数`）；
  - 延伸到序列末尾的段不清仓，留到期末按最后价计值。
- 在 `up` 序列上做 run-length 边界检测（padded 前后补 False，找 F→T / T→F 跳变），
  一次性定位全部买卖点，无 Python 层循环。
- 现金流按时间顺序放入 `flows` 数组做 `np.cumsum`（顺序累加）。首日必无交易，
  故 `flows[0]` 借放初始资金后原地 cumsum——与基线循环的二进制浮点运算顺序
  逐位一致，`final_value` 与改造前完全相同，不是近似相等。
- NaN / inf：浮点比较恒为 False → 视为非上涨日，之后按浮点规则传播，
  与基线循环行为逐位一致（有测试锁定）。

### 2.2 结果缓存（含设计迭代记录）
- 第一版 `lru_cache(tuple(prices))` 基准不达标，分解测量（100 万点）定位瓶颈：
  tuple 键构造 8.6ms + tuple→数组二次转换 25ms + lru_cache 逐元素比较 9ms，
  全在缓存层；且 lru_cache 只能按条数限额，无法约束内存。
- 最终设计：**单次转换 + bytes 键 + 按字节数限额（64MB）的 OrderedDict LRU**：
  - 序列输入先经 `array('d')` 做 C 级转换（比 `np.asarray(list)` 快约一半），
    再 `np.frombuffer` 零拷贝成数组；ndarray 输入走 `np.asarray` 零拷贝；
  - 缓存键 = `arr.tobytes()`：哈希/比较是 C 级 memcmp，远快于 tuple 逐元素比较；
  - 限额按键总字节数 eviction，防大序列撑爆内存；超预算单条不缓存；
  - 缓存值为不可变 `(final_value, trades)` 元组，外层每次构造新 dict 返回，
    调用方改写返回值不会污染缓存；CPython GIL 下各步原子，并发重复计算无害；
  - 附带优点：含 NaN 的输入（tuple 键因 NaN≠NaN 永远无法命中）也能正确命中。

## 3. 基准数据（本机，Python 3.9 + numpy 2.0，重复取最优）
| 规模 | 旧循环 | list 首算 | list 命中 | ndarray 首算 | ndarray 命中 |
|---|---|---|---|---|---|
| 1 千 | 0.07ms | 0.18ms | 0.02ms | 0.01ms | <0.01ms |
| 10 万 | 7.42ms | 5.13ms | 2.09ms | 0.90ms | 0.43ms |
| 100 万 | 71.89ms | 46.41ms | 19.51ms | 5.64ms | 5.44ms |

使用指引：
- **回测管线建议直接传 ndarray**：100 万点首算/命中约 13 倍；
- list 输入命中路径受「证明相等必须读完整个序列」的下限约束（CPython 转换
  约 15ms @百万点），收益 1.5x / 3.7x；
- 小序列（<5 万点）numpy 固定开销占优，一次性调用反而慢于旧循环，但绝对差
  在 0.2ms 以内，且缓存命中后 <0.05ms；不做双路径分派（避免双份正确性负担）。

## 4. 兼容性与边界行为
- 空序列 / 单点序列：无交易步，返回 `{"final_value": 10000.0, "trades": 0}`，与基线一致。
- 全跌 / 全平序列：无现金流，返回初始资金。
- int / float 混合序列、ndarray / tuple / 生成器输入均可；数值统一转 float64，
  与基线结果逐位一致。

## 5. 验证与测试清单（test_backtest.py，10 项）
