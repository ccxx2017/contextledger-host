## 1. 一句话定位
不动回测模块，把数据获取 → 清洗 → 对齐 → 指标计算管线做向量化，
为回测管线提供高吞吐、零拷贝、可复现的数据供给层。

## 2. 现状盘点（评估结论先行）
- **本仓库（task-project）目前不存在数据层代码**：仅 `backtest.py` 及其测试。
  方案 B 的对象尚不存在，首期实质是"定义并新建"，而非"改造存量"。
- 回测 API 直接消费 `Sequence[float]`，说明上游（若存在）在别处完成取数与
  加工；其归属与形态是本方案能否落地的**第一决策点**（见 §8）。
- 可复用资产：方案 A 沉淀的工程结论——缓存键设计教训（逐值比较不可 scaling，
  应按数据版本号键控）、基准先行的验证方法、零拷贝转换路径（`array('d')` /
  `np.frombuffer`）。

## 3. 目标与非目标
目标：
1. 新建 `data_layer`（暂名）模块：加载、清洗对齐、指标计算三段；
2. 全程 numpy 向量化，杜绝 Python 逐行循环处理行情；
3. 输出契约稳定：`np.ndarray (float64)` 直接喂 `run_backtest`，不引入转换开销。

非目标：
- 不改 `backtest.py` / `test_backtest.py`（冻结，验收含"零 diff"检查）；
- 不重写上游数据源对接（首期只做本地文件加载）；
- 不承诺与尚不存在的旧数据层逐位一致（无此对象；改为承诺 dtype 与结果可复现）。

## 4. 范围界定（首期切片建议）
| 子模块 | 首期范围 | 明确不做 |
|---|---|---|
| loader | CSV / parquet 本地行情加载，统一 float64 | 数据库、实时源、鉴权 |
| aligner | 日期对齐、缺失值前向填充、复权因子应用 | 跨市场时区处理 |
| indicators | MA、收益率、波动率等常用指标批量计算 | 自定义表达式引擎 |

## 5. 技术设计要点
- **零拷贝交接**：loader 产出直接为 `np.ndarray(float64)`，向回测传递不做
  tuple/list 落地转换（方案 A 实测：list 转换在百万点级耗 15–25ms，属纯浪费）。
- **数据版本缓存**：缓存键 = 数据文件内容指纹（大小 + mtime + 首尾哈希）或
  上游版本号，避免方案 A 式逐值比较；指标层按 (数据键, 指标参数) 二级键控。
- **dtype 纪律**：全链路 float64 单一 dtype；禁止静默升维/降精度。
- **可复现**：同输入必同输出；清洗规则显式可配（前向/剔除/报错三策略）。
- 依赖：numpy（已有）；pandas 是否引入列为开放问题（见 §8）。

| 风险 | 等级 | 缓解 |
|---|---|---|
| 数据层范围被会上扩大（实时源/多市场涌入首期） | 高 | 按 §4 切片表逐项圈定，超纲一律进 backlog |
