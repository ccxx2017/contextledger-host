## 3. 接口草案（签名级，供评审冻结）
```python
load_prices(source) -> tuple[float, ...]      # source: CSV 路径 / 可迭代数值（形态待 D2 裁定）
clean_prices(prices) -> tuple[float, ...]     # 去 NaN/非有限值、严格升序去重、保序
resample_prices(prices, step) -> tuple[float, ...]  # 等距重采样，step 待定默认值
```
- 返回统一 `tuple`：直接满足冻结 backtest 的入参契约，并天然可作为缓存键。

## 4. 技术选型（决策项 D1：numpy vs 纯标准库）
- 方案 A 实测教训：纯 Python"向量化"（groupby/切片）冷路径反而比简单循环慢约
  4 倍（n=100k：25.11ms vs 6.43ms）——无 C 加速时向量化≠更快。
- 数据层属批量数组运算（过滤/排序/重采样），numpy 预期收益为正；
  纯标准库则零依赖、部署最简。**建议**：若确认数据规模 ≥1e5 点/批或高频批量
  调用，选 numpy；否则纯标准库。以 benchmark 数据会上定夺。
