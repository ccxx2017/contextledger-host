## 二、改造前基线

- 纯 Python 逐 bar 循环：价格高于前一根则买入 1 单位，非上涨则一次性清仓
- 起点 10000.0 现金；返回 `{"final_value", "trades"}`
- 3 项基线测试（空序列 / 单点 / 连涨）

## 三、实现设计

### 3.1 向量化：上涨 run 切分

- `rises = np.diff(p) > 0` 标记所有买入转换点
- 加哨兵 `[False]` 前后缀后，用布尔边界法定位连续上涨 run 的 `starts` / `ends`
- 各 run 买入成本由 `cumsum` 前缀和一次差分得出：`cost = cum[end+1] - cum[start+1]`
- 已闭合 run（后随非上涨）：清仓款 = `prices[end+1] * run长度`，批量结算
- 末尾开放 run：不计清仓款，长度累计为期末持仓，期末按最后一价估值

示例 `[1,2,3,2,3]`：rises=`[T,T,F,T]` → 闭合 run（长度 2，成本 5，清仓价 2.0 得 4）+
开放 run（长度 1，成本 3）；现金流 10000 + 4 − 5 − 3 = 9996，期末持仓 1，
final = 9996 + 1×3 = **9999**。

### 3.2 结果缓存

- `_run_backtest_cached` 挂 `@lru_cache(maxsize=128)`，key 为价格序列的 tuple 副本
- 纯函数无副作用，缓存安全；有界 LRU 防止超长会话下内存无界增长
- 代价：每次调用需 O(n) 的 tuple 转换 + 哈希，超长序列下缓存收益被键构造开销摊薄（实测仍为净收益）

### 3.3 语义口径（定稿）

- `trades` 沿用基线定义：期末持仓数，非成交笔数
- 非上涨（平/跌）触发清仓；NaN 参与比较按"不大于"处理，语义与平价一致
- 数值容差：差分对拍按 < 1e-6 判等
