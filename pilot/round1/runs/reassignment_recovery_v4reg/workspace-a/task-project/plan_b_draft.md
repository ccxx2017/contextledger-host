## 3. 方案 B 目标（建议）

新建 `data.py` 数据层模块，职责链：**加载 → 校验 → 向量化预处理 → 供数**。

向量化首批覆盖操作（建议最小集）：

| 操作 | 实现方式（建议） |
| ---- | ---------------- |
| 价格校验 | NumPy 掩码批检：NaN / 非正值 / 非有限值，报错带首个坏点下标 |
| 收益率 | `simple`: `arr[1:]/arr[:-1] - 1`；`log`: `np.log(arr[1:]/arr[:-1])` |
| 规范化 | `zscore` / `minmax`，纯 NumPy |
| 滑动统计 | 滑动均值 / 滑动波动率（stride 或累加和实现），纯 NumPy，不引 pandas 硬依赖 |

性能目标（建议验收线）：10 万级序列单操作 < 10ms，较等价循环实现 ≥ 5x。

## 4. 接口草案（建议稿，会上定稿）

```python
load_prices(source) -> np.ndarray          # CSV 路径 / 内存序列 → float64 数组
validate_prices(arr) -> np.ndarray         # 原地校验语义，违规抛 ValueError
compute_returns(arr, method="simple") -> np.ndarray
rolling_mean(arr, window) -> np.ndarray
rolling_vol(arr, window) -> np.ndarray
```

设计约定（建议）：

- 全部纯函数、无全局状态；输入输出均为 `np.ndarray`（float64）。
- **数据层默认不做结果缓存**。方案 A 实测教训：以 tuple 为键的 lru_cache
  在 n=100k 时键构建 + 哈希约 2.4ms，吃掉首调收益；无复用证据不引入缓存。
