# 回测模块改造笔记

## 方案 A 范围

对 `backtest.py` 做两项改造，对外语义与基线循环实现完全一致
（上涨日买入 1 份、非上涨日一次性清仓、期末持仓按末日价估值）：

1. **向量化**：以 NumPy 替换逐日循环
2. **结果缓存**：`lru_cache` 按价格序列缓存回测结果，暴露命中统计

## 实现要点（backtest.py）

- `run_backtest` 为公开入口，内部委托 `_backtest_core`（`lru_cache(maxsize=256)`）。
- 缓存键为 `tuple(prices)`，list / tuple 等价序列共享同一缓存项。
- 向量化核心：
  - `up = p[1:] > p[:-1]`：上涨日掩码，买入额 = `p[1:][up].sum()`。
  - `sell_pos = flatnonzero(~up)`：非上涨日即清仓点；各清仓点前连续上涨天数
    由 `diff([-1, sell_pos]) - 1` 得出，卖出额 = 点积 `run_lens · p[1:][sell_pos]`。
  - 末日尾段持仓 = `(m - 1) - 最后清仓点`，按 `p[-1]` 估值。
  - `n < 2` 直接返回初始值 `{final_value: 10000.0, trades: 0}`。
- 缓存防污染：`run_backtest` 返回 `dict(...)` 拷贝，调用方改动不影响缓存。
- `cache_info()` 暴露 hits / misses / maxsize / currsize。

## 等价性验证（test_backtest.py，12 项全绿）

- 基线 3 项：空序列 / 单价 / 单调上涨。
- 随机游走等价：50 组（种子 42）与基线循环实现逐项比对，容差 1e-6。
- 平台期与断崖等价：50 组低基数价格序列（种子 99，制造大量相等价格日），
  容差 1e-9 —— 覆盖 `up` 掩码最易错点：`p[i] == p[i-1]` 属非上涨，须触发清仓。
- 定向边界：全跌（零交易）/ 全涨（持仓到末日）/ 相等价格日清仓 /
  断崖下跌按崩盘价清仓 / 5000 点长序列精度（容差 1e-6）。
- 缓存行为：命中计数递增、返回拷贝可被调用方安全篡改、list 与 tuple 同键。

## 性能冒烟（Windows / Python 3.9，单次最优值，ms）

| n      | 基线循环 | 纯向量化计算 | 首调（含建缓存键） | 缓存命中 |
| ------ | -------- | ------------ | ------------------ | -------- |
| 1,000  | 0.07     | 0.04         | 0.06               | 0.03     |
| 10,000 | 0.66     | 0.37         | 0.52               | 0.26     |
| 100,000| 6.66     | 3.98         | 6.41               | 2.70     |

结论：

- 纯计算向量化稳定快约 1.7–1.8x。
- `lru_cache` 以 tuple 为键，键构建（tuple 转换 + 哈希）为 O(n)：
  n=100k 时该开销（约 2.4ms）几乎吃掉首调收益，命中路径仍比循环快约 2.5x。
- 重复回测同一序列的场景缓存为正收益；若未来大序列重复调用成为热点，
  可评估更低成本的缓存键（如对缓冲区做摘要哈希），当前不在方案 A 范围内。
